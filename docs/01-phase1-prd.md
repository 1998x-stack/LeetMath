# 01｜LeetMath Phase 1 完整 PRD

版本 v0.1 · 2026-11-17 · 状态：设计草案 · Owner：产品负责人（待指派）

## 1. 背景、目标、成功定义

本期交付“可信数学题内容底座 + 可用的 LeetCode 式刷题体验”。首先支持上海高中数学的分层知识点、完整题目与多小问；同时允许接入不同省市、教材版本、试卷、合作出版社和自有原创题库，不引入重复录入和编号冲突。

主要目标：
- T1：编辑人员可以将含多小问、公式和图的数学题录入、独立评分、审校并发布。
- T2：学生能按题目/知识点/难度检索，进入题目、逐问作答并看到可靠反馈。
- T3：导入外部内容后可定位原始来源、授权范围、相似候选及每次转换结果。
- T4：题目/答案修订不会改写历史答题结果，撤稿可以精准生效。
- T5：后台可量化导入质量、题目质量、学习行为和系统可用性。

## 3. 核心流程

### UC-01：手工录入并发布

前置：登录且有 editor 权限；选择 source/rights；题目所在学段、地域目录可选。

步骤：新建题目 → 填共同题干 → 设置学科/学段/课程标签 → 添加 N 个小问并分别选择回答类型 → 填标准答案/解析与评分点 → 关联素材 → 实时数学预览 → 保存草稿 → 点击“送审” → Reviewer 审查数学/排版/权利 → 发布版本 → 公共题库可检索。

规则：至少一个小问；题组的共同题干可为空但每个小问实际展示内容必须非空；单个小问最高分 > 0；总分等于小问满分之和；发布要有有效来源权利依据、可见性、至少一个合格答案、基础知识点、已通过预检；草稿可改，发布版本不可原地更改。

AC：所有小问可单独获取、作答、评分；改草稿不影响历史版本；被拒稿显示拒稿原因并可修订重送。

### UC-02：搜索并刷题

用户从题库页选择高中 → 上海 → 函数与导数 → 难度 7～9，得到可公开展示且已发布、授权有效的题目；可以关键词搜索、按最近更新或难度排序；进入详情显示题干、所有小问、资料来源与修订日期；可逐问提交，确认作答/显示反馈；可收藏、加入错题集、继续下一题。

边界：无结果显示移除筛选建议；发布被撤回的题不再进入搜索；历史提交记录中显示“题目已下架”并隐藏受限内容；同题多来源显示主显示版本及合法来源标识，不重复刷出相同题身份。

AC：筛选在刷新后由 URL 恢复；分页不重复/漏题（固定排序 + 稳定 tie-breaker）；匿名用户可阅读公开题，提交需要登录。

### UC-03：导入新增题库

运营注册新来源 → 补齐版权/授权范围 → 上传 manifest + 内容文件 → schema 校验 → 建批次 → 原始留档并计算 sha256 → 清洗数学排版和图片资源 → 来源键去重 + exact hash → 检出相似候选 → 生成草稿/隔离记录 → 教研处理疑似重复和不可信答案 → 审核发布 → 记录批次报告。

规则：无权利证明不得自动公开；检测到相同 source_id + external_id + external_version 的数据重复时重跑不得新增题目；不同来源出现相似题必须“候选”，不能仅用向量相似度自动合并；来源发生题干/答案变更建立新修订候选；批次失败可重试单条，不重做整个库。

AC：5 次重跑同一个 manifest，题目/外部映射数量不增加；任何公开题均能回查来源与授权依据；批次明细可导出且含失败阶段与错误码。

### UC-04：发现错题/申诉

学生在小问旁报告“答案错误/题干歧义/图片缺失/判题误判” → 创建 issue → 管理员分级 → 教研复核 → 若属于答案修订则生成新版本并执行修订公告 → 对受影响历史提交重新评价或保留原判并标注处理状态（不得悄悄修改）。

AC：用户可查看报告状态；重大错题能立即暂停该小问的自动判题或撤稿；所有操作留存操作人、前后内容与时间。

## 4. 规则细则

### 4.1 题目身份

ProblemID 为内部 UUID，不随来源改变；用户可见题号（如 LM-SH-000001）是平台发行号，可重命名 slug 不可复用。外部题号只在 source 的命名空间内唯一。SourceRecord 支持多对一 Problem 的引用；“完全相同”“推导同构”“参考改编”关系分开记录。

### 4.2 内容结构

题目 = stable identity + revision + common statement + parts[] + attachments[] + metadata。答案与 rubric 跟随 revision / part 版本。内容渲染使用经净化的 Markdown + LaTeX + 白名单素材引用；禁止任意 HTML/脚本。公式存原始 LaTeX 和可选规范化表达式；规范化不是用来改写人类显示原文。

### 4.3 难度模型

难度是 1～10 的 platform_score，附来源、评定人、评定时间和 confidence；原来源 Easy/Medium/Hard 或考试“压轴”另存 source_difficulty，不直接覆盖。知识点关系包括 prerequisite/tested/related，随课程版本变化。

### 4.4 提交与判分

Submission 关联 user_id、problem_revision_id、part_id、answer_spec_version、grader_version、输入快照与评测记录。对数值需声明精度/单位/定义域；符号等价只在明确变量假设下成立；证明题 P0 限“展示解析 + 标记待人工批改”，不能给伪确定性的自动满分。

### 4.5 发布/撤稿

状态：draft → in_review → approved → published → archived/retracted。发布动作应产生不可变 snapshot；修订新建 Revision，旧题解/提交仍指向旧版本；rights hold 会覆盖 published 的前台可见性。撤稿不代表删除审计与成绩，但必须遵循适用的数据保护要求与授权撤回条款。

### 4.6 隐私与公平

学生只看自己的作答历史；教师不能因为可编辑题目就访问全站学生个人数据；运营看聚合统计；管理员敏感操作需审计。学生可报告判题错误；低置信度评分展示“待复核”而非“错误”。

## 6. 优先级与依赖

P1.0：Source + Rights + Taxonomy + Problem/Revision/Part + 发布快照 + 样例数据 + 测试，先于任何学生端批量上线。

P1.1：CMS 编辑、数学渲染、内容预检、审核/发布；依赖 P1.0。

P1.2：题目 API、搜索、题单、题目详情、账号、收藏；依赖已发布内容。

P1.3：Submissions、Rubrics、Judging、历史与错题；依赖稳定 revision 和 part。

P1.4：可插拔批量导入、去重审阅和导入质量报表；可与 P1.2/P1.3 部分并行开发，发布前必须完成功能门槛。

P1.5：版权处置、审计、性能、备份恢复和内容抽检；上线前必须完成 P0 相关门禁。

## 7. 发布验收门槛（必须满足）

- AC-001：首批试点题可完整呈现多小问；随机样本 100% 有来源/权利/可用答案与必要解析。
- AC-002：已发布题创建新版本后，老 Submission 和原分数可查询、原判题器版本可追溯。
- AC-003：同批次重复导入不产生重复 SourceRecord，疑似相似题进入人工审阅。
- AC-004：各型判题完成黄金样例测试；不支持的题型明确展示人工复核或练习模式。
- AC-005：未授权/被撤回内容无法从公开检索、详情或直链获取。
- AC-006：所有写接口校验角色，重大操作都有 audit log。
- AC-007：筛选和分页结果稳定，公式在桌面和移动端正确渲染。
- AC-008：数据库迁移、备份恢复、幂等导入、访问控制与 API 契约测试进入 CI。

## 8. 依赖与未决项

尚须确认：首批合法可用题目范围、授权文本模板、上海课程目录版本、试点学校/教师、是否允许匿名查看解析、校内作业场景是否需要班级隔离。默认设计：公开读仅针对开放授权题；试点运营可先使用原创题；不得因未决项阻断数据模型与本地样例开发。
