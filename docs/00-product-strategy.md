# 00｜LeetMath 产品战略、范围与指标

版本 v0.1 · 2026-11-17 · 状态：待评审。

## 1. 产品定位与问题

LeetMath = 数学版 LeetCode 的学习体验 + 内容治理平台。核心价值不是“题目数量多”，而是题目可检索、可解释、可追溯、可版本化、可作答、可评测，并能长期接入新题库。

现状痛点：（1）跨教材/考试的同题重复、来源不明；（2）数学题的主干与多小问被拍平成一段文本，无法单独计分；（3）图片/公式与正确答案脱节；（4）教师修改已发布题目造成历史记录失效；（5）导入易、清洗审核难；（6）学生只得到“对/错”，难以定位知识点。

## 2. 人群与待完成任务

| 人群 | 核心任务 | Phase 1 交付 |
|---|---|---|
| 学生（首期高中） | 找到合适题、练习、回看错题 | 搜索、题单、答题、答案/解析、进度 |
| 教师/教研 | 录题、拆小问、设答案与评分、审核内容 | CMS 编辑器、预览、审校和批量操作 |
| 题库运营 | 引入不同题源、去重、版本维护和归因 | Source Registry、导入批次、重复候选、审计 |
| 平台管理员 | 权限、版权、质量、系统健康 | RBAC、指标、回滚、监控 |

初期不对外承诺自动生成严谨证明，不将 AI 评分作为不可申诉的唯一依据。

## 3. 核心概念与定位

- Problem：稳定的逻辑题目身份；不等同于某个版本的文本。
- Revision：不可变的题目发布快照（题干、素材、子问、答案、评分规则）；草稿可编辑。
- Part：独立小问，继承共同题干，可分别计分。
- Source Record：来源中的原始题目记录；允许多个来源映射至一个规范 Problem。
- Variant：同构改编、换参、语言转换，不与“完全重复”混淆。
- Attempt/Submission：作答会话与提交，永远绑定 Revision + Part + 判题器版本。
- Rights：授权、归属、展示范围与撤稿限制；权利状态独立于内容质量状态。
- Curriculum Taxonomy：可版本化的知识点树/图；不把上海目录写死在业务表中。

## 4. 北极星与约束指标（建议起步值，待基线校准）

北极星：每周完成至少一组“有效练习”的活跃学习者数。有效练习定义：提交有结果、题目当前可展示、非机器人/内测账号。

质量护栏：
1. 发布题的来源可追溯覆盖率 = 100%。
2. 发布题拥有至少一个经审核标准答案和必要解析的比例 = 100%。
3. 审核抽检中的重大数学错误率目标 < 0.5%；出现 P0 错题必须撤稿或阻断判题。
4. 批量导入重跑重复创建率 = 0（幂等）。
5. 历史作答对应的发布快照可复现比例 = 100%（权利撤稿时保留受控内部审计记录）。
6. P95 题目详情接口 < 500ms（缓存命中/常规负载）；P95 搜索 < 800ms（约定数据规模与部署条件）。
7. 单个采集批次每条记录都有导入状态与失败原因 = 100%。

业务观察：搜索到开题转化率、开题到提交率、答案争议率、审核吞吐、每源有效发布率、同题去重率、题源成本、练习留存。不在无数据前设虚构增长承诺。

## 5. 范围与战略阶段

Phase 1（本期）：内容契约、题库 CRUD、老师 CMS、阅读/搜索/题单、答案判题基础能力、练习进度、数据来源治理、批量导入与权限安全。

Phase 2：验证过的题解扩写、Manim 分镜/源码/视频资产与教师工作台；渲染服务通过资源引用连接，失败不阻塞基本练习。

Phase 3：学生步骤级分析、学习路径、知识掌握模型、可交互数学实验；必须先积累高质量人工审核数据。

## 6. 产品明确不做（Phase 1）

- 不开放无限制网页爬取；无授权来源不得批量复制内容。
- 不做拍照 OCR 自动高准确率承诺；输入管道可以预留 OCR 审核状态。
- 不做自动给高考证明题满分的“黑盒判题”。
- 不上复杂班级排课、支付、付费内容交易、社交排行榜、监考与防作弊。
- 不将 Manim 视频在线生成定义为 P0。
- 不将所有题目强塞单个 JSON 字段或把“来源外部 ID”作为全局主键。

## 7. 启动范围决策

先用“上海高中函数与导数、解析几何、概率统计”中的经授权/原创样例验证数据模型；全面覆盖上海高中题库前，应确认课程目录/版权来源及教研能力。先压通 100～300 道高质量题的全生命周期，再扩成 1 万/10 万题的导入平台。数字是试点规模建议，不是现有数据。
