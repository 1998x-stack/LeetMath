# LeetMath Reasoning Practice — 完整产品需求与交互规范 v0.2

> 状态：研究支持的**设计提案**，非已交付生产版本。对应仓库 `LeetMath/docs/00–12`，不直接覆盖现有 Phase 1 PRD。项目定位为“数学版 LeetCode 的可信题库 × 推理步骤卡 × 可解释的间隔复习”。

## 1. 定义与边界

- **Problem**：稳定问题身份；关联不可变 ProblemRevision、共同题干与多个 RevisionPart。
- **Reasoning Path**：一道小问的某种教师验证解法（坐标法/几何法可分别成为路径）。
- **Reasoning Step**：路径中的一个可描述、可验证、可反馈的推导节点。可构成依赖 DAG 而不只有数组顺序。
- **Recall Cue**：答案未揭晓前的独立提示语，不能在提示中泄漏推导结果。
- **Reasoning Card**：`ProblemRevision + RevisionPart + ReasoningPathVersion + StepVersion + CueVersion` 的具体复习单元。
- **Step Evidence**：学习者对本步骤的自报知晓情况（知道/模糊/不确定）与可能的独立输入、提示、计时、教师判定。
- **Knowledge Snapshot**：由不同类型证据估计的知识点学习状态，版本化、可追溯、样本不足时明确不确定。

**不属于本地 MVP**：官方数学评分、教师 CMS 全功能、Manim MP4 生成、生产数据治理、商用公网部署、经大样本校准的自适应算法。

## 2. 学习流程与页面

| 页面 / 路由 | 主要功能 | 交互验收 |
|---|---|---|
| `/` 学习大厅 | 继续学习、复习到期、领域题卡、筛选 | 每题显示领域、难度、三问数量、最大分、原创示例标识 |
| `/login` 登录弹层 | 本地注册/登录、会话维持 | CSRF 防护；密码 hash，不在前端存储令牌 |
| `/practice/:attempt_id` 训练 | 上进度与自评得分、上中题干和图、左历史、中央当前步骤、右 2D/3D | “知道/模糊/不确定”三键；点后显示参考推导；不能跳到未来答案 |
| 训练最后的知识自评 | 每个考查知识点回答 1–4 级信心 | 全部完成方可标记整题完成，留可解释证据 |
| `/profile` 成长档案 | 训练趋势、雷达、薄弱关键步骤、到期任务、日历 | 表头必须声明“自评证据指数/非考试正确率”，样本量可见 |
| 后续 `/cms` | 教师审核步骤、定权重、知识点链接 | 教师可以 preview 但不可原地修改已发布版本 |

### 2.1 练题页视觉信息架构

```text
┌───────────── 顶部：题号 / 步骤进度 ▰▰▱ / 自评 8.5/14 / XP ──────────────┐
│ 公共题干（最少 18px 字号） | LaTeX / 图片占位与适配 | 小问导航       │
├───────────────┬────────────────────────────┬────────────────────┤
│ 已完成历史     │ 本次“下一步应想到什么？”      │ 函数曲线 / 椭圆 /    │
│ STEP 01 ✓     │ 不提前展示答案                │ Three.js 棱锥       │
│ STEP 02 ~     │ 关键步骤 x 2.0 / 2.0 分        │ 旋转/缩放/俯视等    │
│               │ [我知道] [比较模糊] [没想到]   │                    │
│               │ 评价后揭示数学推导 → 下一步    │                    │
└───────────────┴────────────────────────────┴────────────────────┘
                  结束：知识点 1–4 自评 → 总结与下一步建议
```

历史步骤点击可回看，但不能篡改已提交的自评；如要允许撤回，须采用追加 correction event，不应直接 UPDATE 审计链。手机端历史改为顶部折叠抽屉，主内容单列，3D 区可折叠。

### 2.2 数学显示规则

公共题干使用结构化 rich text blocks：paragraph/inline_math/display_math/image/table/diagram，不拼接不可信 HTML；KaTeX 负责公式，保留有语义的 alt 文本与行内 copy。初版页按原有 seed 结构显示；后续统一到 `MathContentContract v1` 的完整块解析器。排版遵循数学题手机行宽、块级公式可横滚、图像具有 caption、缩放不模糊。

2D：函数定义域、参数 slider、椭圆与直线交点、相关点标注，默认 Canvas/SVG。3D：Three.js WebGLRenderer + OrbitControls、点/棱/面对象、命名视角（正视、俯视、右视、透视）、按题意绘制而不是任意示意。fallback：WebGL 不可用时 SVG 投影；需要告知 fallback 不是自由交互 3D。Manim 视频是额外资源，不阻塞互动练题。

### 2.3 每次评分交互与行为学问题

正确步骤顺序：先阅读 recall cue → 尝试在纸上写出或脑中想出下一步 → 选知道/模糊/不确定 → 参考解法揭晓（含公式、误区说明）→ 下步。第一次出现时提供“知道是主动想出，不是看答案觉得懂”的引导。避免奖励用户选择“知道”，否则数据将系统性失真。

选项文案推荐：

| 自评 | 内部值 | 展示含义 | 后续动作 |
|---|---|---|---|
| 我知道 | know | 在看答案前能明确说出本步 | 正常延后复习 |
| 有些模糊 | fuzzy | 大致方向正确但公式/理由不确定 | 较早重复 + 概念微卡 |
| 没想到 | unsure | 本步思路未主动出现 | 尽快重复 + 补先修概念 |

评分必须展示“自评参考分”，不等价于原卷标准分。辅助揭晓和提示越多，能力证据权重越低。真正考试模式允许独立手写/LaTeX 提交并用 LeetMath `evaluation` 获得数学分，绝不与自评加总。

## 3. 游戏化与保护性设计

「清晰反馈 > 操控性的沉迷」。上方始终可见 1）步骤位置 2）重要步骤权重 3）本轮自评分/上限 4）参与型 XP；关键步骤仅在数学意义明确且教师审校时才标记；完成后高亮“今天改善的知识点”而不是宣称升级数学智商。每日适量目标、允许无惩罚暂停，用户可隐藏 XP；不要用罚分迫使点击“知道”、不要制造无限题流或难以退出的连续签到。

## 4. 知识点与标签三层体系

| 层级 | 示例 | 数据角色 |
|---|---|---|
| Curriculum / Knowledge Nodes | `SH-HS-ANAG-CHORD`, `SH-HS-GEO3-DIHEDRAL` | 已审校、版本化、有先修边和权重的能力评估目标 |
| Tags | `最值`, `直线与椭圆`, `正交投影`, `困难`, `适合动态图` | 检索、题单、课堂主题，不等于能力标签 |
| Error Taxonomy | `MISSING_DOMAIN`, `MISIDENTIFIED_DIHEDRAL_ANGLE` | 误区与个性化提示、知识节点多对多映射 |

一个步骤可能同时测试导数符号与不等式变形；记录 `(step, knowledge, relation_type, weight)`，以规范权重分配。`prerequisite` 不直接视为测验正确。不同知识点关系需带 curriculum_release 身份，避免跨省教材语义合并。

## 5. 用户系统与成长面板

本地体验可创建用户名与密码，单设备多账户隔离。长期用户系统应允许学生/教师/教研/管理员角色，教师默认不能查看非授权学生细粒度历史；支持学校 tenant 时需要追加成员关系、儿童数据保留政策、敏感内容审计、密码恢复、可选 2FA、Rate Limit、会话撤销与备份恢复。

成长面板分四张独立卡：

1. 学习活动：完成轮次、步骤次数、到期卡、有效练习天数。
2. 自评表现：最近练习得分/上限的趋势与关键步骤知道率。
3. 知识证据指数：雷达 + 柱状置信区间 + 样本数 + 最近独立作答结果（有则显示）；数据少时写“证据不足”。
4. 下一个核心提示：聚合最近 `unsure/fuzzy` 的高权重步骤、关联先修缺口，明确“为什么推荐”。

**演示实现局限**：目前雷达是归一化自评加权的描述性指数，不是经过 IRT/BKT 标定的掌握度；若当前无验证性答案证据，不能将显示值命名为官方真实掌握率。

## 6. 指标与实验

建议北极星：`每周完成 ≥1 个有效推理训练环节的活跃学习者`，护栏为平均单次练习时间、关键步骤独立迁移测验正确率、误报自评比例、复习到期积压、可退出率与未成年人心理负担。用两组用户比较“纯题目重复”和“关键步骤 + 变式”的 7/14 天延迟迁移表现；不要仅以 XP、点击次数或短期停留时间判断教学效果。

## 7. 可验收用例

- AC-R01：同题多小问共享题干；不同小问的步骤和答案都能单独计分，`sum(step.max_points) = part.max_score`。
- AC-R02：关键步骤比辅助步骤分值高；但点击“知道”仅产生 self-rating，不能写入正式 `evaluations`。
- AC-R03：一条步评使用相同 idempotency key 重放不产生第二次事件、分数或 XP。
- AC-R04：新建用户不能读取旧用户的 Attempt、诊断、雷达或复习调度。
- AC-R05：最后一步完成必须提交所有 tested topics 的 1–4 自评才能结束。
- AC-R06：初版可以从旧 SQLite 题库导入完整 3 道原创题与 28 步；后续正式版遵守 PostgreSQL 权威库和版权门禁。
- AC-R07：3D 棱锥可选择俯/正/侧/透视视图，失去 WebGL 时清楚显示降级提示。
- AC-R08：未来更新题解为新版本后，老 Attempt 与老步骤评价仍可追溯。
- AC-R09：匿名用户不能提交自评分；服务端验证所有训练接口的用户与 CSRF。
- AC-R10：移动端在 375px 可用，公式不会将整个页面撑出屏幕，键盘焦点可见。
