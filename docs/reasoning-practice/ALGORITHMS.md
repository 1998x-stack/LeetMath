# 算法设计：评分、调度、知识证据、推荐、奖励

> 算法状态分级：下列 `v0-local` 规则已在 MVP 内实现；`v1-production` 是建议路线，不是假装已经完成的功能。任何数字为预设可配置参数，不代表经教育实验验证。

## 1. 把三种分数严格隔离

| 名称 | 数据来源 | 显示位置 | 可否声称代表数学真实水平 |
|---|---|---|---|
| 步骤回忆自评分 (`self_recall_score`) | 学生点“我知道/模糊/不确定” | 本轮练习页顶部、训练趋势 | **不能**；反映主观主动回忆 |
| 已验证作答分 (`validated_math_score`) | 学生独立给出数学答案，可靠判题器或教师按 rubric 评分 | 正式考试/作答记录 | 可称本次该题数学得分，不能直接泛化为所有知识点能力 |
| 参与积分 (`engagement_xp`) | 完成被分配的思考步骤、学习目标 | 游戏化个人页 | 完全不是数学分数 |

### 1.1 逐步骤评分公式

设 Part 的真实 rubrics 总分为 `P`。Step `i` 由教师指派基础得分比例 `r_i>0`、关键性 `c_i>0`，则可选最终分值归一化：

\[
 w_i = P \frac{r_i c_i}{\sum_j r_jc_j},\qquad \sum_i w_i=P.
\]

对已有教研分值 `w_i`，优先直接使用，不需要再次乘关键系数，否则会和原评分标准冲突。MVP 直接用旧 SQLite steps 的 `score_point`，并自动验证 `sum(w_i)=part.max_score`。

对自评选项：`g(know)=1.0`、`g(fuzzy)=0.45`、`g(unsure)=0`，当次自评分：

\[
 R_{part}=\sum_i w_i\,g(rating_i),\qquad R_{problem}=\sum_{part}R_{part}.
\]

例如 14 分大题，关键步骤 3 分且用户选择“模糊”，本步自评 `3×0.45=1.35`。此值只在自评维度有效。系统不应让用户发现“点知道给更多 XP”，因此积分必须和自评选项脱钩。首次揭晓前的 cue 必须不泄露答案；如果在点击前已查看完整答案，要记录 `revealed_before_rating=true` 并大幅降低这条证据在画像的权重。

### 1.2 MVP 规则与未来策略

MVP 只基于每个步骤原始 rubric points，并以 `0/.45/1` 加权；没有按重要性重新定权。关键步骤由已有分值 `>=2` 的演示阈值判断（仅限这些样例），生产环境必须人工审校 criticality 与 rubric 映射，避免以同一阈值横跨所有题型。

## 2. 间隔重复调度：两个层次

**MVP（已实现的简化规则）**：当日 `know -> 7 天后`、`fuzzy -> 3 天后`、`unsure -> 1 天后`。每张卡的 `due_at` 按 UTC 记录，复习状态由 `(user_id, step_id)` 唯一定位。到期专题训练在同一小问中只取一张卡，初步防止兄弟提示泄漏。

**正式产品建议 FSRS**：采集 graded history，使用与 FSRS 兼容的记忆状态 `S=stability, D=difficulty, R=retrievability`。可采用开源兼容实现或独立模块，保存 scheduler_version、desired_retention、review_history。Three-grade UI 不能直接假称与 FSRS 四个评分完全一致：推荐显式映射 `unsure -> Again`，`fuzzy -> Hard`，`know -> Good`；Easy 可通过一个单独明确选项或对严格校验的容易题采用，不能偷偷把 know 映射 Easy。生产中仍需保留原 UI 自评分而不只存 FSRS 的四类等级。

**数学特有的策略**：如果同一道题的所有步骤都进入复习池，同一轮只显示一个同兄弟组；当记忆稳定但迁移能力不足时优先推荐同构变式题，避免刷熟题导致虚假掌握；下一步“原题回忆 vs 变式题”由 `learning_mode` 区分。

## 3. 知识掌握画像：证据而不是凭空估计

MVP 使用清晰的平滑描述性指标（只解释学生自报，不用于正式分级）：

- `alpha=2`,`beta=2` 的弱先验；
- 每条步骤自评以原小步骤 rubric 分值为权，加入 `alpha += weight * g(rating)`，`beta += weight * (1-g(rating))`；
- 每次知识自评 level 1–4 对应 `(level-1)/3`，以仅 0.5 的低权重进入；
- 展示 `100 * alpha/(alpha+beta)` 与 `step_observations`、`self_assessments`。

注意：这个结果是**自评证据指数**而非经过参数标定的真实能力概率，和先验与给分权重都有关系；样本少不能比较不同学生，雷达需要同时显示样本量。

正式版建议在数据充足时加入 `verified_submission`、`teacher_assessment`；每个证据记录 `evidence_kind, source_id, weight, reliability, time, content_revision, algorithm_version`。先按客观证据与自评分别显示，再对比标注“自我感知与独立正确率差距”。待有足量数据及教师校准题后，再试 BKT/IRT 或心理测量方法。不得宣称已获得准确掌握率。

## 4. 复习推荐与薄弱环节

推荐候选包括：已到期推理卡、最近不确定的高权重步骤、与这些步骤相连的先修知识卡、未见过的同构变式。候选过滤：内容版权、发布状态、课程版本、已修订卡片、前置能力、当日 sibling burial。可配置初版评分：

\[
 priority = 0.40\times due + 0.35\times weakness + 0.15\times prereq\_gap + 0.10\times novelty.
\]

所有输入规范化在 [0,1]；这是待验证的启发式，而非经实验优化过的算法。冷启动可按教师推荐题单 + 用户选的教材章次 + 难度分层。每个推荐应返回可见解释，例如“你在解析几何面积最值的两个关键步骤都选了‘不确定’，先回顾弦长与面积关系”。

MVP 目前只展示最近 `fuzzy/unsure` 的关键步骤提示以及按 due_at 的训练队列，**没有实现上式多目标排序**。

## 5. 参与积分（XP）

MVP 每次新步骤首次被用户在某 UTC 日评价，给 `5 + min(5, floor(teacher_points))` 点 XP；当天重复同一步不重复奖励，防止重复刷积分。这与知道/模糊/不确定无关；用户诚实报告不会失去 XP。正式版应考虑 daily_soft_cap、退出提醒、隐藏积分开关以及本地日历时区；不以延长会话或惩罚断签来追求使用时长。

## 6. 安全与公平的典型边界

- 自评主观偏差：不同学生信心水平不同，不可用于教师硬性排名或学习诊断结论。
- 数学可靠性：已验证解法与教师 rubric 是内容治理对象，自动生成步骤不能跳过审校。
- 同题记忆污染：兄弟步同轮限制、随机参数变式、延迟测验；不是无限重复完整题。
- 隐私：学习历史属于学生个人信息，不进入公开 analytics 或第三方日志；小样本雷达不用于做不可解释的人生判断。
- 模型追踪：指标、FSRS 参数、推荐权重和课程版本变动时留下版本号，必要时可以基于原始事件重算。

## 7. 验收算法的单元测试列表

分数守恒（每问权重总和）、关键步骤比一般步骤重、0/0.45/1 分支、未知 rating 422、浮点四舍五入、重复 event_id 无二次分与 XP、连续复习时 scheduler 状态更新、改变 Step 版本不影响旧事件、同题 sibling burial、用户跨区时区、低样本雷达标注、退版权后的推荐隐藏、FSRS 模型迁移可回放。
